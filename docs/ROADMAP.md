## 1. 定位与技术栈

**职业定位**：懂 AI 的 **Go 后端工程师**（不做低端 Agent 开发）

**投递方向**（三条腿走路）：
- Go 后端（大厂 / 云原生 / 基础设施）
- AI 平台 / AI Infra
- Python 后端（AI / 数据方向）

**技术栈**

| 层 | 选型 | 说明 |
|---|---|---|
| 主语言 | **Go 1.23+** | 学习成本仅 Java 的 1/3，岗位质量高 |
| AI 语言 | **Python 3.12 + FastAPI** | 复用已有基础 |
| 框架 | Gin / Kratos | Go Web 框架 |
| 数据库 | PostgreSQL 16 | 面试必问 + pgvector 支持 AI |
| 缓存 | Redis | 缓存 / 限流 / 分布式锁 |
| AI | LLM / RAG / **GraphRAG** | 借力图算法科研 |
| 前端 | Vue 3 + TS | 最小可用即可，不求精 |
| 部署 | Docker + GitHub Actions | Vercel + Zeabur/Render + Neon |

**项目架构**（Go + Python 双服务）

```
leetnote-api   (Go + Gin)          → 用户/题目/笔记 CRUD，高并发 API
leetnote-ai    (Python + FastAPI)  → RAG 相似题检索、LLM 解法讲解、复习卡生成
        ↑↓ gRPC
    PostgreSQL (+ pgvector) + Redis
```

## 4. 刷题方法论

**语言选择：主刷 Python，辅刷 Go。**

- **Python**：面试主力。代码短、写得快，面试时间效率最高
- **Go**：学 Go 期间用 Go 重刷 Hot 100 中约 50 题（学语言 + 面试展示）
- 面试时：投 Go 岗且 Go 写题速度达标 → 用 Go；时间紧 → 用 Python，提前和面试官说明

**跟随资源：灵茶山艾府（灵神）**

先完整看一遍他的「**如何科学刷题**」，再按他的专题题单走。

**核心方法：专题连做 + 间隔二刷**

```
第 1 遍：同一专题连做 8–10 题 → 形成肌肉记忆
第 2 遍：3 天后重做错题
第 3 遍：1 周后重做仍然卡的题
```

**每题笔记模板**（记进 LeetNote）：
```
思路：一句话
关键：这题的核心技巧是什么
坑点：我卡在哪
复杂度：时间 / 空间
```

**题量目标**

| 时间 | 累计题量 |
|---|---|
| 2026.12 | 180+ |
| 2027.03 | 350 |
| 2027.06 | 400 |
| 面试期 | 保持每天 1–2 题手感 |

## 11. 风险与调整机制

| 风险 | 应对 |
|---|---|
| 课程/科研挤占时间 | 优先保算法（1h 不能断），项目可顺延，但不超过 2 周 |
| 算法进度落后 | 砍专题广度，保专题深度——**二刷 > 新题** |
| Go 岗位不及预期 | 用 Python + AI 能力投 AI 平台 / Python 后端，底座通用 |
| AI 方向变化快 | 押注**工程能力**而非具体框架，框架会变，系统能力不变 |
| 项目做不完 | 砍前端精细度，保后端 + AI 的深度（那才是简历重点） |
| 面试受挫 | 每场必复盘，把没答上的写进八股清单——**面试本身就是最好的复习** |

**每 4 周检查一次**：算法进度是否达标？项目是否在推进？如果连续 2 周落后，砍掉非核心项。
